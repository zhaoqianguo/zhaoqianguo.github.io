状态没有自己的名字

发表于2026-11-12|随笔
|阅读量:

函数组件每次渲染，就是把那个函数重新调一遍。局部变量活不过这一次调用，useState 给出的值凭什么还在？状态得挂在函数外面某个和组件实例绑在一起的地方。

React 没让调用方给状态起名字，也没要求传 id。它按调用顺序发号。

一个数组和一个游标

我在 Node v22.22.2 上抄了个最小实现，二十行出头：

useState 拿不到变量名。const [count, setCount] 里的 count 是解构出来给人看的，React 只看这是本次渲染里第几个 hook。每次 render 先把游标归零再从头数，第三个 useState 就去 hooks[2] 拿上次存的东西。

跑三个 hook 是 render1: 1 b true | hooks.length = 3，改两个值再来一次是 render2: 2 B2 true | hooks.length = 3。数组没长。

规矩从这儿长出来。我把第二个 hook 塞进 if (!skip)，同一个组件跑两遍：

没有异常。

hooks 从 3 个变成 2 个，第三个 hook 顺位读到原本属于第二个的 true，后面每一个都往前挪一格。DEV 下 React 会抛 Rendered fewer hooks than expected，那是校验，不是机制。机制是位置对齐，少一次调用整排就错位，而且不报错、不中断。

还有一个跑过才看得见的：setA(n => n + 1) 连着调两次，下一次 render 拿到 3 而不是 2。两个 updater 都排进 queue，render 时依次 apply，函数式更新拿到的是队列里上一条 apply 完的结果，不是组件闭包里那个旧值。我那个实现里 hook.queue.length = 0 必须放在 apply 之后，放前面就吞掉更新，这一行我挪过一次。

源码里换成了链表

真实 React 不用全局数组。react main 分支的 packages/react-reconciler/src/ReactFiberHooks.js 里，983 行 mountWorkInProgressHook() 建出来的节点长这样：

996 行把它挂到 currentlyRenderingFiber.memoizedState = workInProgressHook = hook，1004 行 updateWorkInProgressHook() 顺着 next 往后走。链表挂在 fiber 上而不是全局，和双缓冲配套：重渲染时按位置 clone 或复用节点，两个 render 各数各的链。容器换了，「第几个」没变，顶层调用那条规则也就没变。

再往上一层是 dispatcher。505 行 renderWithHooks() 在 562 到 566 行按 current === null || current.memoizedState === null 决定把 ReactSharedInternals.H 设成 HooksDispatcherOnMount 还是 HooksDispatcherOnUpdate；渲染一结束，660 行和 940 行换回 ContextOnlyDispatcher，那个对象里 useCallback: throwInvalidHookError。所以 Invalid hook call 不是 React 在检查你把 hook 写在了哪，是 dispatcher 已经换成只负责抛错的版本，事件回调里再调就撞上它。同一个 useState，mount 和 update 走两套实现，调用处一个字都不用改。这一层我以前跳过去看，只当是个内部开关，其实它顺带解释了「为什么只能在 React 函数里调用」。

代价是顺序成了协议，条件、循环、try/catch 里都不能调。想改规则，得先改存储方式。

React 19 那个 use 正好从反面印证。npm registry 上 react latest 是 19.3.1，官方文档 react.dev/reference/react/use 写着 Despite its name, use is not a Hook. Unlike Hooks, it can be called inside loops and conditional statements like if.。它能待在 if 里，因为压根不占链表槽位，走的是 Suspense 那条路：pending 时组件 suspend，最近的 Suspense boundary 显示 fallback。同一页还提了不能拿 try/catch 包 use，它内部就是靠抛出来接上 Suspense 的。规则没有松动，是它不在规则管的那套数据结构里。

写这类实现，我习惯先把最小版本跑一遍再翻源码。那份 175910 字节的 ReactFiberHooks.js 留着没删，下回想看 updateWorkInProgressHook 怎么复用节点，从 1004 行往下翻就行。
